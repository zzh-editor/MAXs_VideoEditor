# 内容驱动的动画 b-roll

用于课程、讲座或口播里需要视觉解释的知识点。判断对象是“观众要理解的关系”，不按术语数量自动堆卡片。

## 在哪一步做：字幕之后，主项目内

b-roll 不在转写之前做，也不跟精剪同时做。默认顺序：转写或复用字幕 → 保守精剪 → 字幕对时与清理（字幕完成）→ 扫描内容并提出动画 b-roll 候选 → 用户确认 → 制作并加入主 HyperFrames 项目。用户已明确指定图解内容和字幕范围时，跳过候选确认，按指定范围直接制作。每条视频都要完成一次内容扫描；用户本轮只强调剪辑或字幕，也不能因此跳过这一步。字幕没定稿之前不做图解，区间会跟着剪辑变。

判定只看字幕文本：这段在讲关系、层级、空间范围、因果或多步流程，而且画面本身讲不清，就进候选；只是一句术语、菜单路径、快捷键、单步操作，录屏已经能表达，就不进候选。

候选清单每条写清：字幕编号与源时间、一句话主张、要用动画表达的关系、拟用的视觉动作、预计时长（通常 15–30 秒）。有多条时按“必须画图才讲得清”排序，一次给用户确认，确认后才制作。清单为空就写明未发现适合动画解释的内容，不为了凑数做图。用户可拒绝候选或指定其中几条。

## 项目结构与可编辑性

默认在主项目的 `compositions/` 中建立 b-roll 子组合，并在 `index.html` 加入独立 `data-track-kind="graphics"` 轨道。动画保持无声；原视频音轨和 Studio 字幕轨继续独立、可编辑，不能把 b-roll 烧进 A-roll。只有用户明确要求单独交付 b-roll 时，才在源素材同级建 `<素材名>-broll-<主题>/` 独立项目；已有项目不因为这条规则搬家。

## 何时询问

- 用户已经明确要求 b-roll/图解/Three.js 动画：直接依据用户指定的字幕范围制作，不再询问要不要做。
- 字幕讲到抽象关系、空间、因果、层级或多步骤流程，原文已有类比/例子：将原类比图形化，并以一帧/一个 beat 映射回知识点。
- 概念主要靠学术表述，缺少具体例子；图形演示能让关系更容易看懂：先用一次短问题询问是否制作图形化 b-roll。列出准备可视化的概念及预计时长，不先创作未经同意的模型或类比。
- 只是一个有明确名称的对象/菜单路径/快捷键，字幕和录屏已能解释：保留原画面或使用轻量 tips，不升级成一段 3D 动画。

推荐问法：“这段主要在讲【概念】；字幕没有给具体例子。我可以做一段约 15–30 秒的图形化 b-roll 来展示【关系/过程】。要加吗？”

## 从字幕到分镜

1. 只读取用户指定且确认正确的最终简体 SRT。按编号选取闭区间，保留每条原始时间和文本，计算源区间：`首条 start` 至 `末条 end`。用户纠正输入后，停止读取此前被纠正的音频/字幕路径。
2. 将这一段压缩为一条主张、一组角色/对象和它们之间的因果、空间或时间关系。标记字幕直接支持的事实与不能从字幕得出的推断。
3. 动画必须表达该段内容本身的关系或变化，例如轨迹、父子层级、前后状态、因果链或多步过程。先选 2D 还是 3D，再选择能表达关系的运动；不加无关粒子、泛用转场或只为装饰的模型。
4. 有原生比喻时建立双向映射表（类比对象 → 知识对象），例如“电梯/乘客 → 父物体/子物体”，并说明类比边界。不要把所有参数都拟人化或额外制造第二个类比。
5. 给用户简要分镜，写明字幕来源及时间、动画要表达什么、预期时长和会不会遮住录屏操作。用户已明确要求该图解并指定字幕范围时，把分镜作为执行说明直接制作，不重复询问；若只是本技能提出的候选，必须先等用户确认。新增模型、镜头或解释必须符合用户要求或已确认的分镜，不得悄悄加入字幕没有支持的事实。
6. 概念 b-roll 默认 15–30 秒、最多 30 秒，除非用户明确给更长上限。设置清楚的开场问题、关系演示、概念回扣和结果停留；按源字幕时间顺序为动画 cue 标注来源。时长是图解自身的时间线，不拉伸、快放或改写原口播音频。
7. 将动画作为主项目中的静音可编辑子组合，原声留在 A-roll，字幕继续走单独字幕轨。按剪辑清单把源时间映射到成片时间，剪辑变更后从字幕源区间重算。

### 按字幕推进图解

- 为每个图解列出字幕 cue 与对应的视觉状态，子组合内动画时刻用 `cue.start - graphic.start` 换算。节点、连线、标签或数值在口播提到时分阶段出现；较长图解不得在开头几秒演完后静止覆盖剩余讲解，也不为填时长添加无关呼吸动画。
- 关键内容应分布到整段口播，结尾留可读停顿并在下一段前退场。抽查每个 cue 边界、阶段中点和最后 hold，确认文字先于或同时出现，不提前剧透后续关系。

### 可复用音效

- 需要音效时先用 `media-use` 检查项目或全局候选，优先复用已登记的短音效；新素材按技能流程加入项目 manifest。一个 click 可用于少量字幕强调和节点显现，一个 whoosh 可复用在图解进出场，不为每条字幕另找音效。
- 只在能衬托画面动作时使用，控制音量并避开密集口播；按精确时间放在字幕强调、图解转场或分阶段节点出现处。没有合适素材就省略，不能用音效铺满整段。

### Maya 父子级 / 世界空间示范

对于“电梯载人”的已给定字幕，可采用以下映射，逐帧以该文件实际文字为准：

| 类比 | Maya 概念 | 可显示的事实 |
| --- | --- | --- |
| 楼宇及楼层刻度 | 世界空间参考 | 观察整体运动的外部坐标参照 |
| 电梯轿厢 | 父物体/offset group | 父级从 Y=0 移至 Y=10 |
| 轿厢内乘客 | 子物体/controller | 子级局部 Y 保持 0 |
| 乘客随轿厢到达 10 楼 | 子物体世界变换 | 纯 Y 平移示例中世界 Y 变为 10 |
| Maya 节点树 | offset group → controller | 父组承担位移，controller 局部通道保持干净 |

一般 3D 变换用矩阵关系 `M_world(child) = M_world(parent) × M_local(child)`。示例中的 `10 + 0 = 10` 仅解释无旋转/缩放的纯平移，不得泛化成所有层级变换都做向量相加。字幕支持的显示值如有疑义，就只标“示意”，不要虚构 Maya 操作或节点行为。

## Three.js 与品牌

- 技研Labs 色彩与全画幅背景遵守 `brand-and-opening.md` 的图表基线：`#ADF911` 作为唯一品牌强调色，小面积落点；配纸灰 `#F0EFEB`、炭黑 `#1C1C1A`、辅助灰 `#6A6963` 和线灰 `#DEDDD6`。绿色不铺大块、不用于浅底小字；不引入紫蓝霓虹或无意义彩色粒子。
- LeonaDesign 色彩：`#FEF201` 作为唯一品牌强调色，黄色底用黑字；其余延用 MAXs 的字幕位置、高亮与图解节奏，不使用 MAXs 或技研Labs 标识素材。
- 所有新增文字沿用 MiSans VF。字幕已有英文术语时保留其准确写法，不额外翻译/改写原字幕内容。
- Three.js 场景是时间的纯函数：响应 HyperFrames `hf-seek`，按当前时间直接设定 mesh、相机、坐标、面板状态后 render。禁止 `requestAnimationFrame` 驱动主动画、计时器、`Date.now()`、未设种子的随机数和 seek 时网络加载。
- 固定渲染尺寸和 pixel ratio；几何体优先程序化生成。本技能项目固定 Three.js 版本并把模块存入项目 `assets/vendor/`，最终项目不依赖运行时 CDN。
- 根组合明确设置 `data-duration`，以适配 Three runtime；文本、标注、坐标面板可以作为同期 HTML/CSS 层，品牌与场景表现遵守同一 16:9 `frame.md`。
- 暗底版本基准：`#161616` 底 + `#ADF911` 强调色。安装包的 `README.md` 展示可复用的静态图解样式；样片只是视觉参考，实际内容仍须绑定本条视频字幕。

## 运动、透视与文案

- **相机默认固定不动。** 不做推进、不做平移、不做绕转，不用镜头运动去补静止段落——镜头一动，图形元素在画面里的位置就跟着变，讲解型图形会显得漂。镜头只保留构图需要的那一次固定机位。需要让画面活起来，靠图形自身的动画或形状变化。
- **画面要活就动图形本身。** 静止段落里加活力，加在图形上而不是镜头上：线条自己画出来（`geometry.setDrawRange` 逐段画）、槽位逐个点亮或逐个预亮、整个阵列闪一下再退、标牌跟着图形出现。预演用的动作用低亮度，短促，结束后收干净，别把后面要讲的那一次提前讲掉。
- **相邻两段的内容不要互相侵入。** 上一段的图形要在下一段开始前收干净（淡出结束时间早于下一段淡入开始时间），下一段的元素不要提前出现；抽帧看交接处，确认没有两个段落的图形同时压在画面上。
- **同一段动画涉及多个图形时，用形状变化带动视线。** 例如方框无缝变成圆、阵型重排、粒子场从一种分布连续形变到另一种。做法是同一批对象连续插值到新形状（走缓动曲线，可以加一点弧线），不是两套状态之间淡入淡出切换；右侧文本跟着这一步换。
- **所有过渡走非线性曲线。** 淡入淡出、出现、消失、位移、缩放一律用三次贝塞尔缓动，禁止线性插值。物理运动（粒子匀速飞出、匀速位移）保持线性，那是速度而不是缓动。缓动实现用 CSS `cubic-bezier` 同解：

```js
const cubicBezier = (x1, y1, x2, y2) => {
  const A = (a, b) => 1 - 3 * b + 3 * a;
  const B = (a, b) => 3 * b - 6 * a;
  const C = a => 3 * a;
  const calc = (t, a, b) => ((A(a, b) * t + B(a, b)) * t + C(a)) * t;
  const slope = (t, a, b) => 3 * A(a, b) * t * t + 2 * B(a, b) * t + C(a);
  return x => {
    if (x <= 0) return 0;
    if (x >= 1) return 1;
    let t = x;
    for (let i = 0; i < 6; i += 1) {
      const d = slope(t, x1, x2);
      if (d === 0) break;
      const err = calc(t, x1, x2) - x;
      if (Math.abs(err) < 1e-6) return calc(t, y1, y2);
      t -= err / d;
    }
    let lo = 0;
    let hi = 1;
    t = x;
    for (let i = 0; i < 24; i += 1) {
      const v = calc(t, x1, x2);
      if (Math.abs(v - x) < 1e-6) break;
      if (v > x) hi = t; else lo = t;
      t = (lo + hi) / 2;
    }
    return calc(t, y1, y2);
  };
};
const easeOut = cubicBezier(0.22, 1, 0.36, 1);
const easeInOut = cubicBezier(0.65, 0, 0.35, 1);
const easeIn = cubicBezier(0.55, 0, 0.85, 0.25);
const span = (time, start, end, curve = easeInOut) => curve(clamp01((time - start) / (end - start)));
```

- **平面图形正视，不带透视。** 流程图、网格、柱状图这类平面内容，相机放在目标正对轴上（位置与 lookAt 同 x/y），不要侧向偏移，也不要把平面物体再倾斜一次；否则方框会变成梯形，读起来像透视错误。需要体积感时用正交投影的立方体、线框表达，不要靠斜视角造透视。
- **说明文字按讲给同学听的口吻写。** 用具体动词和名词，不用抽象名词堆叠，不用"赋能/闭环/底层逻辑"这类词，也不用成对的否定句式（"不是 X，而是 Y"）。标题控制在 7 个汉字以内，避免换行出现孤字；正文一句话一件事，术语沿用字幕原写法。
- 不加“蓝色表示当前重点”这类解释装饰色的小字。只有不同颜色、线型或点型代表真实数据类别，且读者需要说明时才加语义图例。
- 不做独立漂浮花字。只在全屏 A-Roll 的原字幕内高亮实际说出的关键词/短语，图表 + PIP 段不高亮；字幕没有该词就不补写，普通句子也不为凑频率而整行变色。

## 图解选择与风格

参考 [cathrynlavery/diagram-design](https://github.com/cathrynlavery/diagram-design) 的关系分类，不复制其 HTML/SVG 模板。先问图比一句话或表格多说明了什么，再判断语义关系，最后选一个最合适的图形类型；一张图只讲一个主关系，静帧本身也要读得懂。

### 可选图形类型

- **结构与系统：** Architecture、Architecture delta、IT current-state、Deployment、High-Level、Nested、Tree、Org chart、Layer stack、Dependency graph、UML class、ER/data model、Database schema、Medallion、Exploded axonometric、Axonometric plan。
- **流程与时间：** Flowchart、Sequence、State machine、Timeline、Swimlane、Process、Gantt、Story map、Kanban、User journey、Service blueprint、Loop。
- **数据比较：** Quadrant、Radar、Polar、Bar/dumbbell、Line（slopegraph、ridgeline、streamgraph、bump）、Scatter（bubble、beeswarm、box plot）、Waterfall、Treemap/marimekko、Heatmap、Venn、Pyramid/funnel。
- **流向与诊断：** Sankey、Fishbone、Wardley map、Data flow、DP integration、DP security matrix。

### 图形取舍

- 优先用布局表达关系，线条只在确有连接含义时添加；能合并的重复节点直接合并。通常每张图控制在 9 个主节点、12 条连线以内，超出就拆成总览和细节两张。
- 图形布局尽量落在 4px 网格；用细边线、平直连接和明确层级，不加阴影，不把所有节点做成同尺寸圆角卡片。色彩按账号规则，只突出 1–2 个焦点。
- 数据图按数据类型选图：类别比较用柱状图，趋势用折线，阶段与等待用时间线/泳道，部分与整体用 treemap，流量分流用 Sankey，多因素取舍用 quadrant；不为了新鲜而使用难读的图型。
- 平面关系图正视表达，不用倾斜透视制造装饰感。只有空间、装配顺序或场地本身承载信息时，才用 axonometric。
- 避免把 Diagram Design 的 45 个名字当模板清单。读取该类型的真实例图和限制后再选；已有图表不因这些规则自动重画。

## 交付与对时

默认在主项目的 Studio graphics 轨道交付动画，并记录字幕编号、源时间、成片时间和对应的子组合。动画盖住录屏期间继续使用 A-roll 原声和字幕时间，不重复混入 source audio；动画结束后回到原画面。用户要求独立交付时再给单独项目或文件。字幕 SRT 与 Studio 字幕轨保持一致，不把第二套文字烧进 b-roll。

验证静态布局、主从运动、局部/世界坐标、首尾状态和 caption-safe 区域。使用 `check --strict --snapshots` 检查，再逐张查看关键帧。如果 Three 画布未被 DOM 布局审计覆盖，另外读取关键帧快照确认网格、几何体与文字不出画、不互相遮挡。先打开 Studio 预览检查图解；最终 MP4 的渲染授权遵循 `SKILL.md` 的“预览交付”：用户已明确要求渲染时，检查通过后直接渲染，否则等待预览确认。
