# 图表文案

用于 MAXs、技研Labs、LeonaDesign 的图表标题、节点文字、大字报和提问卡。视觉、布局与动效见 `brand-and-opening.md` 和 `conceptual-broll.md`；本文件只管写什么字。

## 判定顺序

动笔前依次确定：观众是谁 → 他拿到什么 → 数字从哪来 → 有没有讲者内部语汇。任一步答不上，先回字幕找依据，不写。

## 七条

### R1 标题写所得，不写讲者叙事

- 写观众能带走的结果，不写这段口播的讲述顺序。「一线为何常更新」→「一线师资优势」；「建模流程推演」→「AI 建模省时间」。
- 「为何／怎么／是什么／如何」式标题只在提问卡里出现，其余位置改用结果句。

### R2 每条图标一个受众

- 受众取自片子里真实出现过的去向：升学、求职、转行入行、接单。不写「大家」「所有人」。
- 形式：主标题下独立一行标签，或主结论外的细线框。标签用强调色描边，不用色块铺底；一张图只一个。
- 示例：`学习的目的` + 蓝框 `升学与求职`。
- 标签只挂主结论，不挂每个节点。每张图都挂框等于没挂。

### R3 品牌主张显式写出来

- 口播出现「我们这边 MAXs 最大的特点」「我们跟别家不一样」这类自我定位时，标题直接写「MAXs 特色」或口播原词，不降级成「作品集导师」「行业导师」这类通用词。
- 副行放依据，`cards.json` 记 `claim_cue`。口播没有依据就不写，不替账号编卖点。

### R4 字数分两档

- 主标题 ≤7 汉字，避免折行孤字。
- 受众标签和副行独立成行，可到 12 字。
- 超长就把从句拆到副行，不缩字号。

### R5 一张图一个结论句

- 主结论用结果动词：最终落脚、极大缩短、省掉、拿到。不写「关系」「流程」「逻辑」这类结构名。
- 过程分支压到副行，超过三项直接删。
- 结论句优先用口播原话的判断；口播没下判断就只画关系，不替讲者下结论。

### R6 数字走口径表

- 数字一律阿拉伯数字；区间用连字符：`3–12 个月`、`5–8 年`，数字与单位之间一个空格。
- 取值顺序：用户口径 → 口播原话。冲突时用用户口径，并记录来源 cue。
- 没有口径且口播是近似说法时，写原话能支持的值（「4–12 个月」），不外推、不美化取整。

### R7 讲者内部语汇要翻译

- 口播顺口说的「这个」「那边」「我们组」，图表里换成具体名词。
- 行业缩写保留原写法（ACCD、TA、地编），不翻译、不括注。

## 数字口径表

用户确认过的口径写进项目 `BRIEF.md` 的「口径」段，本文件不存固定值。

| 项 | 取法 |
| --- | --- |
| 时长 | 用户口径优先，示例「3–12 个月」依据字幕「四五个月 一年的时间」 |
| 年限 | 同上，示例「5–8 年」 |
| 薪资、人数、名次 | 只在口播明确说出时写，不做区间外推 |

- 数字节点在 `cards.json` 记 `number_cue`（字幕编号），交付时连 `claim_cue` 一起汇报，供用户逐条抽查。
- 口径与口播不一致、用户又没给口径时，先问一次，不默认外推。

## 交付前四问

1. 这条给谁看？（受众标签在不在）
2. 他看完拿到什么？（主结论是不是结果句）
3. 数字对不对？（对得上 `number_cue` 或口径表）
4. 有没有内部语汇没翻译？（「这个」「那边」「我们组」）

四问全过才进 `check`。不过关就改文案，不靠加节点、调动画或补装饰填。
