# 导入后一次性确认

新视频先导入素材并检查源片、媒体信息、同目录 SRT 和已有工程记录，再在任何剪辑、字幕改写或图形写入前收集未决选择。恢复已有工程时读取 `BRIEF.md` 和现有时间线，只问缺失或发生变化的选择。

用当前 host 的阻塞式问题机制一次提交所有相关问题。支持批量问题时放进同一次调用；不支持时发一份编号问卷并等一次答复。不要把同一批选择拆到转写、增强、剪辑和图解阶段重复询问。只问会改变本片结果、且用户尚未回答的事项。

按素材与任务裁剪问卷，通常涵盖：

- 账号与视频类型：MAXs、技研Labs、LeonaDesign；课程切片、直播切片或口播。
- 剪辑范围：保留导入片，或允许剪掉明确的准备段、空白和废弃重录；用户已给具体区间时按原话记录。默认不改用户已精剪的片。
- 转写和字幕：若缺少 SRT 且没有已配置的转写引擎，询问引擎；同时询问是否润色、中英混排空格、括注、领域自动检测或手动指定、以及字幕 diff 的审批方式。若 Video-Transcribe 配置中已有引擎，沿用配置，不在问卷重复询问。中文简体是默认，不问语言，除非用户要求翻译或其他文字系统。
- 图解：允许根据字幕直接制作有字幕依据的候选、只列候选等用户再次确认，或不加图解。只有明确选择“直接制作”才预批准候选；没有合适候选时不硬凑。
- 交付：用户未明确要求渲染时，可选择检查后停在 Studio，或检查通过后直接渲染。已明确要求渲染时不重复问。

账号的强调色、标题板规则、字幕样式和安全区直接按 `references/brand-and-opening.md` 使用，不列成问卷选项。标题清楚时按源文件有效标题排版；标题缺失或互相矛盾时才问用户。

## 把答案带过检查点

将每个答案写进项目 `BRIEF.md`，并在对应项目阶段引用它。粗剪、转写、字幕增强、diff、图解候选和交付仍按 `SKILL.md` 的顺序执行；只有当某检查点的实际提案落在用户已批准的范围内，才记录“已由导入问卷预先确认”并继续，不重复弹窗或提问。字幕 diff 只在用户预批准的修改类别内自动接受；可能改变语义的修正必须停下询问。提案超出批准范围、出现新信息可能改变原选择，或答案不明确时，只就变化部分询问。

调用 `video-transcribe` 或 `srt-enhancer` 时，把问卷中与其有关的选择作为用户原答传入。子技能照常运行转写、术语、混排、diff 和验证步骤；不得为已回答的引擎、润色、领域、空格或括注再问一次。若子技能遇到问卷未覆盖的新授权或秘密（例如 Groq API Key），仍按它自己的安全检查点处理。
