# 字幕技能交接

通过 OpenCode 的 skill 工具加载 `video-transcribe` 和 `srt-enhancer`，由返回的 base directory 定位各自脚本。复用其现有环境、模型和配置；不复制实现，不建立新的 Whisper 环境，不在日志里输出 API Key。

## 转写阶段

无可靠字幕时，调用 `video-transcribe` 的本地文件管线。保留其引擎选择、L3 断句复核、润色确认等检查点。这里需要原始 SRT、`raw.srt.words.json` 和 cleanup sidecar 作为后续输入；sidecar 是转写技能自然产物，不是另写一种对用户的字幕输出格式。

告诉用户本次准备先精剪、后增强；到润色确认时由用户选择“本轮跳过润色”，不能替用户选择。若用户选择先增强，按原管线完整执行并记录来源：后续完整保留的字幕复用已增强文本，不再次增强；跨切口文字先在原始词级数据上处理，再仅审核新增或受影响的字幕修改。

### 简体中文字幕硬门槛

- 转写时沿用 `video-transcribe` 的简体中文提示。原始 SRT 和 words sidecar 按 ASR 原样保存；若原始字幕仍出现繁体，在现有的字幕文字校对阶段制作简体工作稿，不重跑转写，也不新增必需依赖。
- 只转换字幕和匹配的新增中文文字，不改编号、时间戳、时长、cue 数、说话内容或英文技术标识符。原始转写保留不动，词级时间继续以原始 sidecar 为准。
- 转换后比较 SRT 编号、时间戳、时长和 cue 数，必须完全一致；再做 Unicode 脚本检查并审核文本 diff，确保中文全部为简体。完成后打开 Studio 交给用户目视检查，agent 不读截图或视频帧。
- 如果发现繁体字无法可靠转为简体，保留原始文件并把相关 cue 标为待确认；不能把繁体字幕当成最终版本交付。

结束时建议用户保留临时文件，说明词级数据用于后续对时。在其清理前，把剪辑所需 sidecar 复制到本项目 `transcript/`。各源文件使用独立工作目录，避免同名 `tmp/raw.srt` 串片。新生成的 WAV/缓存与原视频通过明确路径关联。

## 精剪后增强

原始字幕完成词级剪切拆分后，检查工作 SRT 是否为简体；发现繁体就在同一轮字幕文字校对中修正，再完成剪辑映射并交给 `srt-enhancer`。完成领域检测、用户领域/混排/括注选择、术语校准、确定性处理、AI 复核和 diff 审核。增强输出再次检查中文脚本；需要修正时纳入同一份 diff，记录实际返回路径作为最终字幕源。

文字改动不得由 video-edit 私自跳过审核。翻译只有用户明确要求时执行。tips 卡片单独承载解释，不能为了生成 tips 自动开启字幕括注。用户拒绝增强时保留映射后的原始字幕并说明。

### 用户指定的字幕文字修订

- 用户只要求改屏幕字幕时，只改字幕文字，不剪音频、不改原始转写；保持该 cue 的时间和分段，除非用户也要求调整时间。
- Studio 字幕轨和最终交付 SRT 必须取自同一份修订稿。保留源 SRT、已审核基线和 Hook 版等不同用途的文件；生成新版本，不覆盖基线。渲染时把该 SRT 复制到 `renders/<MP4文件名去扩展名>.srt`，不能从另一版字幕生成配套文件。
- 若删词后与相邻 cue 连读不通，先检查整句原文并只调整确有必要的字幕文字，不补造原声里没有的词。

技能间文档如果引用了过期步骤编号，以当前被调用技能的具名步骤为准。当前 `srt-enhancer` 将修改集中到最终 diff 审核；不要再根据旧的调用摘要增加一轮 Config 审核。实际互相冲突且不能据当前入口解决时，说明冲突并停在该交接处。

## 竖屏和词级时间

画幅明确为 9:16 时才调用 `srt-enhancer` 的竖屏后续管线。传入的 words 必须已经映射到同一成片时间轴；不能将源视频绝对时间直接搭配成片 SRT。文字修改后无法逐字对齐时按该技能的降级规则输出句级时间，明确比例估时不代表实际词级同步。

增强完成后的验证按字幕技能自己的流程执行，不重复运行相同的清理和术语替换。Studio 字幕必须是独立可编辑的 `captions` 子组合轨，SRT 与它来自同一份最终简体 SRT。视频阶段只额外检查剪辑接缝、片头偏移、字幕时间和遮挡；烧录字幕是默认模式，只有用户明确要求无字幕时才用临时导出副本隐藏字幕轨。

## 渲染字幕交付

- 每次 MP4 渲染完成后，把当前最终简体 SRT 复制到 `renders/`，文件主名与 MP4 完全相同，例如 `renders/clip.mp4` 配 `renders/clip.srt`。无论是否烧录字幕，SRT 都随成片交付。
- 复制前确认字幕文件与 Studio 轨逐条一致；不要重转写、重排时间或覆盖原始字幕。没有最终字幕源时，不造空 SRT，说明缺少文件并暂停声称交付齐全。

## 竖屏字幕位置默认

- 字幕样式按 `brand-and-opening.md` 的「直播切片 / 口播成片基线」：黑 42% 胶囊底、`600 48px/1.18`、`max-width: 864px`、关键词蓝底白字。不要用纯白字加描边，也不要把整行铺成蓝色。
- 屏幕字幕固定单行。按目标字体、字号和可用宽度测算行宽；过长时按语义和可靠词级时间拆成连续 cue，保留原文、总时长及 cue 间停顿。不得靠缩到难读或让浏览器自动折成两行来适配。生成后用字符数/测量结果检查最长 cue，并同步更新 Studio 轨和外部 SRT；实际画面由用户在 Studio 检查。
- 48px 字号下约 17 个全角字宽到顶。拆分脚本要断言每句宽度，并在 `transcript/` 留一份“新 cue → 原 cue”映射；高亮词和音效拍点靠这份映射回到原句，避免拆句后强调丢失。
- 竖屏字幕使用两个独立位置模式，不把所有 cue 绑到同一个 `top` 值。
- 全屏 A-Roll 跟随首条审核字幕的位置，默认上沿为画布高度的 69.6%。MAXs 参考 cue“今天我们来聊一个话题”在 2160×3840 画布中的上沿为 2672.425px，换算到 1080×1920 约为 1336px。
- 上方图表 + 底部 1/3 PIP 时，跟随图表段参考 cue“第一个是学校排名”，默认上沿为画布高度的 60.4%。MAXs 参考位置在 2160×3840 中为 2320px，换算到 1080×1920 为 1160px。
- MAXs 图表主体的红框安全区见 `brand-and-opening.md`；图表内容须在字幕 cue 上沿之前结束，不能压进 chart-PIP 字幕带。
- 按 cue 时间窗判断它处于全屏 A-Roll 还是 chart-PIP，分别用独立 CSS class/token。计算 cue 与布局窗口的实际重叠时长，只有 chart-PIP 覆盖超过 cue 一半时才归入 chart-PIP；否则归入全屏位置，避免图表退场后字幕仍留在上方。用户给了参考 cue 时，以该 cue 为准。
- 新的 9:16 视频默认使用全屏 A-Roll 位置；出现 chart-PIP 时切到第二个位置。目标平台有自己的字幕安全区时，再按平台 UI 调整。

## 字幕高亮

- 不另建漂浮花字层。只在全屏 A-Roll 且字幕含有值得强调的词/短语时，在原字幕对应文字上高亮；高亮只包住词/短语，不给整行换底色。
- 不为迁就花字改写或补造字幕；找不到对应文字时省略该次强调。SRT 原文与时间不因此改动。
- 3–5 秒是检查关键词的节奏，不是强制出花字的间隔。没有合适关键词就跳过该次，等下一个有意义的词/短语；不要用普通字幕填空。
- 前一分钟要主动检查强调密度，围绕口播中的主张、转折、数字和具体结果安排原字幕内高亮；避免连续几秒只有同一画面和无强调字幕，也不要为凑频率高亮虚词。
- 例如“他是知道你可能”不高亮；“去学的这个专业本身”只高亮“专业本身”。遇到图表或底部 PIP 时不做此类强调。
